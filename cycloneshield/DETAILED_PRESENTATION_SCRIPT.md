# CycloneShield: Detailed Five-Minute Live Presentation Script

This is the operator's script for a strict **5-minute presentation followed by 5 minutes of jury Q&A**. It is deliberately specific about which data is historical, cached, estimated, synthetic, or live. Rehearse the spoken words and clicks together; the click cues are not spoken.

## First: know what the demo actually is

The deployed URL previously loaded as a Streamlit Community Cloud app. In the last deployment check, the vision pane showed **Zero-Key Calibrated Vision Mode**, and no local application key was configured. A key pasted into `.env.example` does not configure either the local app or Streamlit Community Cloud. In a prior check, the hosted app's model menu was also behind the code in the working tree. **Do not promise that current hosted behavior matches un-deployed local code.**

Before rehearsal, establish which mode the actual deployed version is in:

1. In Streamlit Community Cloud, add a rotated Gemini key under **App settings → Secrets** (TOML, such as `GEMINI_API_KEY = "..."`). Never put the value in `.env.example`, source code, slides, screen sharing, or Git.
2. Publish the intended code to the branch connected to the Streamlit app, wait for deployment, and reload the public URL.
3. Confirm the vision model menu matches the intended code and the badge says the key is **detected, not yet verified**.
4. Upload/select a disaster image and explicitly press **Run Damage Triage**. The successful response must show an explicit live-response confirmation. A key-presence badge by itself is not proof of API access.
5. If the request fails, receives a non-success response, or the app is on an older revision, use the offline version of the script below. Never call the benchmark result "Gemini analysis."
6. Do not call the hosted app Cloud Run. The public demo was Streamlit Community Cloud. Cloud Run is a separate deployment option in the repository and needs its own actual deployment and URL.

## Five-minute timing and setup

**Goal:** use the app live, with at most one slide or architecture view. The selected spoken path is about 535–550 words, depending on the triage result; rehearse the click cues so they fit inside five minutes. The Gemini and offline passages are alternatives: speak only the one matching the visible result.

Before the room:

- Open the public deployment in the presentation browser, wait until all widgets finish rendering, and keep the first scenario at **West Bengal → REMAL**.
- Ensure the current UI has been deployed. Verify all eight primary tabs are visible; test each planned click once.
- If doing live Gemini: test one non-sensitive sample image and see the explicit live-response confirmation. Do not use an exposed or unrotated key.
- If live Gemini is unavailable, deliberately present the offline path and use the offline wording below.
- Check that the language you plan to show is available and that audio can actually play. If the network blocks audio, skip playback rather than waiting.
- Close email/chat notifications, hide API-key settings and terminals, and put a five-minute timer where only the presenter can see it.
- Have the recorded demo ready as a backup, but start with the deployed product and call the recording a backup, not the live system.

## Exact click-by-click script

### 0:00–0:25 — Open with the problem

**Click / point:** Stay on the initial situation view. Point to the storm/state heading, risk badge, road/facility KPIs, and estimated-surge qualifier.

**Say:**

> “Good morning. During a cyclone, the track is only the beginning. A district operations team needs to decide which roads may become inaccessible, which hospitals or shelters need contingencies, and how warnings can reach people if cellular service fails. Census 2011-era data put India’s coastal-district population at over 188 million. CycloneShield is a decision-support prototype that connects a storm scenario to district lifelines and preparedness actions.”

**If a metric is challenged immediately:** say that the screen is a scenario-based screening estimate, not a current IMD warning or measured impact.

### 0:25–0:55 — Explain the state and cyclone selectors

**Click:** Open the state dropdown without changing it. Briefly show five options, then leave West Bengal selected. Open the cyclone dropdown, point to historical event names and the custom-track option, then dismiss it without loading a fabricated bulletin.

**Say:**

> “The prototype has five state configurations: West Bengal, Odisha, Andhra Pradesh, Tamil Nadu, and Gujarat. Switching state changes configured cyclone choices, district records or fallback, simulator profile, and regional language. It does not connect to that state’s control room or fetch its current data. Historical tracks use the bundled NOAA-derived catalog first; BigQuery is a fallback when Google Cloud credentials and a project are configured.”

**Do not say:** “It will automatically load live data for West Bengal.” The state switch selects data/configuration already available to the app.

### 0:55–1:10 — Explain language selection

**Click:** Open the language dropdown and show English, Hindi, Bengali, Odia, Telugu, Tamil, Gujarati. Choose Bengali for West Bengal or another language you have rehearsed.

**Say:**

> “The interface offers seven languages, with a regional default by state. Broadcasts use prepared language templates and an audio-synthesis path—not a live Google Translation call here. Agencies and local speakers must review every safety message.”

### 1:10–1:55 — Situation and hazard-map tab (Tab 1)

**Click:** Tab **1. Situation & Hazard Maps**. Point to map, layer selector, and selected district inspector. Change the map layer once if the UI is responsive. Then choose one district in the inspector and point to its score, tier, population, and action.

**Say:**

> “This interactive map plots a selected storm against configured district profiles; it is not a live satellite feed. Tracks may come from the historical bundle. Risk rows and facility counts use scenario rules, not a fresh live overlay of assets. Surge is a screening estimate; population is a Census-era reference. These results do not replace an IMD forecast or official decision.”

**Point to the qualifiers:** estimated surge, baseline/open data, scenario status.

### 1:55–2:20 — Voice alerts and CAP export (Tab 2)

**Click:** Tab **2. Voice Alerts & Broadcast Hub**. Point to SMS, WhatsApp, public-address text; then the XML preview and download button. Download only if already tested and convenient.

**Say:**

> “Here the scenario becomes copy-ready messages and a CAP 1.2 XML export. This demo does not send alerts to SACHET, carriers, or the public. Voice has Google Cloud Text-to-Speech and fallback paths; I claim a live voice service only if verified in this run.”

### 2:20–2:55 — Photo triage / Google AI (Tab 3)

**Click:** Tab **3. Ground Damage Photo Triage**. Show the status badge, sample scene, and model selector. Press **Run Damage Triage** once if you have confirmed that the connected deployment has the latest code.

**Live-Gemini script — use only if a successful live response is visibly confirmed:**

> “This is the post-impact workflow. Gemini Vision returned this image’s structured observations, severity, access implications, and equipment suggestions. The live confirmation verifies this request reached Gemini. These are not ground truth; a responder must verify them.”

**Offline/fallback script — if no verified live response:**

> “This is an offline benchmark reference, not Gemini analysis of the image. It demonstrates the workflow without credentials; I’m not claiming live image understanding.”

**Do not say:** that confidence shown by an offline benchmark is Gemini confidence, or that a key-detected badge proves the request succeeded.

### 2:55–3:12 — Multi-district risk matrix (Tab 4)

**Click:** Tab **4. Multi-District Risk Matrix**. Point to rank, risk score, facilities, roads, action directive, and CSV download.

**Say:**

> “The matrix compares configured districts and exports CSV. Its scores are scenario-based screening outputs, not a live incident feed or verified impact report. A state partner must validate its boundaries, assets, population, and thresholds.”

### 3:12–3:35 — What-if simulator (Tab 5)

**Click:** Tab **5. What-If Landfall Simulator**. Click **Spring Tide (+1.5m)** and point to the sliders and updated table. Avoid rapidly dragging sliders.

**Say:**

> “This is sensitivity analysis: vary surge, wind, or rainfall and a local scikit-learn model recalculates screening scores for a configured state profile. Training used synthetic physics-inspired data, not verified damage records. This compares scenarios; it is not a validated forecast.”

### 3:35–3:52 — Parametric insurance (Tab 6)

**Click:** Tab **6. Parametric Insurance Triggers**. Point to trigger tier and payout matrix. Avoid describing it as an active policy.

**Say:**

> “This demonstrates illustrative wind and surge thresholds mapped to payout tiers. They are assumptions—not an insurance contract, live financial product, or money transfer.”

### 3:52–4:15 — Real-time meteorology (Tab 7)

**Click:** Tab **7. Real-Time Met Feed**. Point first to the status/source/time badge. Show the weather forecast and marine forecast panels only if their badges say **LIVE**. If either is estimated, say so and move on.

**Say:**

> “This tab requests a 72-hour Open-Meteo forecast and marine data for configured state coordinates. The badge and retrieval time distinguish live responses from fallback estimates. This is not an official IMD forecast, and this separate feed does not currently drive the risk KPIs or simulator.”

### 4:15–4:40 — Architecture (Tab 8)

**Click:** Tab **8. Technical Architecture & Evaluator Audit**. Open the BigQuery sub-tab and briefly point at SQL. Optionally point to Cloud Run sub-tab; don't read the Dockerfile.

**Say:**

> “The application is Python and Streamlit. It includes an optional Gemini Vision path for explicit photo triage, a BigQuery path for NOAA history, and optional Google Cloud Text-to-Speech. The simulator runs locally. This demo is hosted on Streamlit Community Cloud; Cloud Run and Vertex AI are deployment blueprints, not its current runtime.”

### 4:40–4:52 — Scale and impact

**Click / point:** Return to the state/language controls if safe, otherwise stay put.

**Say:**

> “Scaling means state-by-state data and workflow validation, not just a dropdown. The five configurations and seven language choices are a starting point. The 188 million figure describes population scale, not people already protected.”

### 4:52–5:00 — Close

**Say:**

> “We’re seeking one state partner for a controlled data-validation and tabletop pilot. Thank you.”

**Stop at five minutes.** Do not open a second demo while the jury is waiting for Q&A.

## One-sentence answers during the demo

- **“Is that live?”** “The UI is live; the displayed scenario data are cached/configured unless I explicitly confirm a successful live service request.”
- **“Will West Bengal load new data?”** “It switches to West Bengal’s configured districts, storm choices, risk profile, and regional-language default; it does not automatically fetch current West Bengal agency data.”
- **“Is the map a real-time satellite view?”** “No. It visualizes a configured scenario using bundled geospatial baselines and map tiles.”
- **“Are these official warnings?”** “No. They are draft decision-support messages; an authorized agency must validate and approve any warning.”
- **“Does it use Gemini?”** “Gemini code is present. In this run I claim it only if the current request displays successful live confirmation.”
- **“Did Gemini write these broadcasts?”** “No. The dashboard uses fixed multilingual templates. Gemini advisory-generation code is present in the repository, but this display does not invoke it.”
